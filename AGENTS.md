# AGENTS.md

Instructions for an AI agent contributing to **minder-data-provider** — an MIT,
open-source universal React/Next.js data layer (`useMinder` + `minder()`) built
on TanStack Query v5, with platform adapters and 9 certified provider
integrations. Read this before editing anything in this repo.

## Repo layout

- `src/` — library source. Key areas: `core/` (`minder()`, `MinderDataProvider`,
  config plumbing), `hooks/` (`useMinder`, capability-contract hooks),
  `auth/`, `cache/`, `websocket/`, `upload/`, `security/`, `platform/`
  (per-runtime adapters), `platforms/` (the `/web`, `/nextjs`, `/native`, etc.
  entry-point files), `config/`, `errors/`, `constants/enums.ts`.
- `providers/<name>/` — one directory per certified provider (clerk, firebase,
  razorpay, sentry, stripe, supabase, authjs, auth0, cognito). Each has its own
  `src/`, `mock.ts` (zero-key mock mode), `example.ts`, `README.md`,
  `provider.test.ts`, `manifest.json`.
- `tests/` — Jest specs (jsdom env, ts-jest, `*.test.ts` / `*.test.tsx`).
  `providers/<name>/provider.test.ts` covers that provider instead.
- `docs/` — API_REFERENCE.md, USAGE_GUIDE.md, EXAMPLES.md, MIGRATION_GUIDE.md,
  product/SUPPORT_MATRIX.md. Update the relevant doc in the **same** change as
  any behavior change — never as a follow-up.
- `__snapshots__/api/` — committed public-API snapshots (runtime export names +
  `.d.ts` surface per subpath). `npm run verify:api` checks the built `dist/`
  against these; `npm run snapshot:api` regenerates them.
- `bin/minder.js` — CLI entry. `scripts/` — build/verify/release tooling
  (Node scripts, not part of the published API).
- `dist/` and `coverage/` exist on disk but are **build output** — never
  hand-edit them; they're gitignored and regenerated by `npm run build`.

## Verification gate — run before claiming anything is done

```bash
npm run type-check && npm run lint:check && npm test && npm run build && npm run verify-build
```

Run `npm run verify:api` too if the change touches any exported symbol, type,
or the `exports` map in `package.json`. Run `npm run verify:treeshake` after
changing what a subpath exports, and `npm run measure:bundles` /
`npm run budgets:check` after a change to core (non-optional) code paths.
Release-grade work additionally runs `npm run release:check`. A task is not
"done" without this command's real output — no self-reported success.

Jest coverage thresholds (global): **57% branches / 51% functions / 63% lines
/ 63% statements** — a change must not drop them. `npm run test:coverage`
reports the current numbers.

## Test conventions

- Jest + `ts-jest`, `testEnvironment: jsdom`, setup file `tests/setup.js`.
- New tests live in `tests/*.test.ts(x)` (or beside the provider they cover in
  `providers/<name>/provider.test.ts`), matching the existing naming style
  (kebab/short descriptive names, e.g. `auth-fail-closed.test.ts`).
- Prefer the `minder-data-provider/testing` toolkit (mock `ApiClient`, plugin
  fixture factory, contract-replay helper) over hand-rolled mocks when testing
  provider/adapter code — it's framework-agnostic and already used repo-wide.
- Security-sensitive behavior (JWT fail-closed, secret redaction, sanitizer
  fail-closed) has dedicated `*-security-audit.test.tsx` / `*-fail-closed.test.ts`
  specs — extend those rather than starting a parallel suite.

## Semver rules (public API is sacred)

- Any change touching an **exported symbol, type, or the `exports` map** in
  `package.json` needs an explicit semver call-out (patch/minor/major) in the
  PR/commit description, plus an updated `__snapshots__/api/` baseline
  (`npm run snapshot:api`) checked in alongside the code change.
- Breaking changes require: a major-version bump *or* explicit owner sign-off
  to ship inside a minor (as this repo's 2.2.0 line has done), a
  `docs/MIGRATION_GUIDE.md` entry, and a `CHANGELOG.md` entry — **in the same
  change**, not deferred.
- Every subpath export must stay independently tree-shakeable — don't add a
  cross-subpath import that defeats `verify:treeshake`.
- Platform/provider support-matrix labels (Confirmed/Experimental/Unknown/
  Inferred-works/Planned) change only with real evidence (a runnable example +
  CI test for "Confirmed"). Never upgrade a label optimistically.

## Do not touch

- `.claude/` and `CLAUDE.md` — gitignored operator state, out of scope for
  library contributions.
- `dist/`, `coverage/` — generated; edit the `src/` that produces them instead.
- Root `*.tgz` packed artifacts (gitignored) — never read or edit.
- Don't add a new runtime dependency without flagging it first — provider SDKs
  are optional `peerDependencies`, and the runtime `dependencies` list
  (currently `axios`, `dompurify`) is intentionally minimal.
- Don't touch `src/security`, the JWT/session fail-closed logic, or the
  DOMPurify sanitizer's fail-closed path without treating it as
  security-sensitive: preserve "fail closed, never open" behavior exactly.
