# Stripe Provider (Plan C — wave ③) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: superpowers:subagent-driven-development. Orchestrator validates, gates, commits per task. Same protocol as Plans A/B.

**Goal:** Payments provider — the server-boundary showcase: checkout sessions created server-side (secret key never near the browser), webhook verification on the F-02 primitive, mock checkout for zero-key UI work, first real use of CLI route scaffolding.

**Architecture:** `providers/stripe/` certifiable dir mirroring Supabase's layout. **Zero-dependency server core**: checkout-session creation via `fetch` to `https://api.stripe.com/v1/checkout/sessions` (form-encoded) — edge-safe, no SDK required; the official `stripe` npm package is an OPTIONAL peer surfaced only through `getProviderClient()` (lazy import, helpful error if absent). Client side implements `PaymentsContract.createCheckout` by POSTing to the app's scaffolded route (path configurable, default `/api/minder/stripe/checkout`). Webhook: Stripe's `stripe-signature` header packs `t=<ts>,v1=<hex>` into one value — F-02's `WebhookVerifyOptions` gains an optional `parseSignatureHeader?: (raw: string) => { signature: string; timestamp?: string } | null` (minimal, tested extension to src/server/webhooks.ts; default behavior unchanged); the Stripe provider supplies the parser and `payloadFormat` `${t}.${body}`.

**Credentials:** `publishableKey` (clientSafe — register via `registerClientSafeProviderKeys('stripe', ['publishableKey','checkoutPath','mock'])`), `secretKey` + `webhookSecret` (serverOnly, `CredentialInput` only). All test values runtime-generated (`'sk_test_' + suffix` CONCATENATED — never a scanner-shaped literal; lesson 4a4f84c).
