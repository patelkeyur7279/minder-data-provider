> Every "Fixed" above was verified on both the success path and a genuine FAILURE path (dead port /
> refused request / fresh, cold module graph) — see `tests/wire/method-contract.mjs` and

> project's own repeated experience (this is the third such incident), actually verified.

> **Rule (strengthened 2026-08-26):** "Confirmed" requires a runnable example app + tests
> exercising it in CI, **and**, for anything that makes a network request, at least one test that
> asserts the actual wire content (HTTP method, URL/path, request body) rather than only that the
> call resolved or returned `success: true`. The prior version of this rule (2026-07-18) was fully
> satisfied by tests that call an endpoint and check the response shape — that is exactly how the
> five core defects above (C1–C5) survived all pre-existing CI legs across every "Confirmed"
> framework row below: no example ever asserted what actually reached the wire. Wire-level
> assertions now live in `tests/wire/*.mjs` (a real `node:http` server + the packed tarball,
> CI job `wire` / `npm run test:wire`, 33/34 cases passing) and are **framework-agnostic** — they
> exercise the shared core request-construction path the same way regardless of which framework's
> example app is running, and explicitly include FAILURE-path cases (dead ports, refused/malformed
> requests), not just happy paths. Per-framework example CI legs (`app-router-example`,
> `vite-example`, …) still mostly prove "boots, renders, and a request resolves" for that
> framework's own SSR/bundling mechanics — most do **not** independently re-assert method/body on
> the wire, so treat "Confirmed" below as "this framework boots and completes real round trips,
> and the shared request-construction core is wire-verified separately" rather than "every feature
> was independently proven on this specific framework." (Evidence rule as of 2026-07-18: test suite
> = 86 suites / 1592 tests, jsdom + React 19.)

> **Node runtime baseline: Node 20+** (`engines.node >= 20`, CI matrix = 20, 22). Node 18 was
> dropped — it is EOL (2025-04) and, concretely, lacks a **global WebCrypto** (`crypto.subtle`),
> which the edge-safe webhook HMAC verification (`src/server/webhooks.ts`) requires. WebCrypto is
> global on Node 20+ and on every edge/browser/Deno/Bun runtime, so 20 is the honest floor. Node
> 18 users can still consume most of the package but must polyfill `globalThis.crypto` to verify
> webhooks.
